# skbtop

`skbtop` v0.1.0 测量 Linux skb 在 IPv4/IPv6 本机 INPUT、本机 OUTPUT、路由/NAT 与桥转发路径上已观测到的时延，按接口和有向接口对区分指定观测点之间的栈处理、出口排队与总时延。

## 安装

目前尚未发布公开 Release 或 skbtop 预编译附件。静态构建 workflow 面向 ARMv7 hard-float、ARM64 与 x86_64，这不表示已有可下载产物。开发安装见[仓库手册](https://github.com/calcky/tools/blob/master/skbtop/README.md)。安装后的程序在 `PATH` 上使用不带架构后缀的名称 `skbtop`。

跟踪需要 root，以及内核允许 BPF 操作、提供 BTF 和所需跟踪 hook。在需要观测的网络命名空间内运行；静态链接用户态程序不会补齐内核缺失的能力。

## 常用命令

```sh
skbtop
skbtop -i eth0,eth1
skbtop -i eth0 -i eth1 -d 0.5
skbtop -c 5
skbtop -c 60 -T 60 -o capture
skbtop -i eth0,eth1 -m 262144 -g 4096 -c 10 -o capture
skbtop -h
skbtop -v
```

省略 `-i` 时，观测当前网络命名空间内全部非 loopback 接口。采集期间持续发现接口的新建、删除、改名和 ifindex 复用；不同接口生命周期保留独立身份。设备删除时立即禁用其跟踪，复用同一索引的新设备不会继承该生命周期的统计。其他网络命名空间不在视图范围内。

不指定 `-c` 时，实时窗口需要终端。`-T` 只限制时长，不改变输出模式；脚本或重定向记录请使用 `-c N`。

## 参数

```text
skbtop [-i IFACE] [-d SEC] [-c N] [-T SEC] [-m N] [-g N] [-o DIR] [-h/-v]
```

| 参数 | 含义 |
| --- | --- |
| `-i IFACE` | 选择接口，可用逗号分隔或重复指定 `-i`；默认观测当前网络命名空间全部非 loopback 接口。 |
| `-d SEC` | 刷新/采样间隔，单位秒；默认 `1`。 |
| `-c N` | 输出 N 个纯文本区间快照，不打开实时窗口。 |
| `-T SEC` | 达到指定采集时长后退出，单位秒。 |
| `-m N` | 在途起源关联与发送关联的合计容量；默认 `262144`。这是关联条目预算，不是报文数量。 |
| `-g N` | 有向路径表最大条目数；默认 `4096`。这是容量，不是分组模式。 |
| `-o DIR` | 在 DIR 中保存区间 JSONL、`summary.json` 与独立 `report.html`。 |
| `-h` | 显示帮助。 |
| `-v` | 显示版本（`skbtop 0.1.0`）。 |

## 阅读实时视图

窗口分为 INPUT、OUTPUT 与 FORWARD 三部分。INPUT 和 OUTPUT 按本机接口显示；FORWARD 把两个接口归为一组，每个方向独立一行，例如 `eth0 -> eth1` 和 `eth1 -> eth0`。同接口 hairpin，例如 `eth0 -> eth0`，也保留独立行。转发统计区分路由/NAT 与桥转发。

用 `Tab`/`Shift-Tab` 切换区域，方向键或 `j/k` 选择行，PageUp/PageDown 或 Home/End 翻页和定位。点击表头按该列排序，同时聚焦所点击的区域；排序对三个区域共同生效。切换到数字列时默认降序，PATH 默认按名称升序，再次点击反转，当前排序列显示箭头。更改排序会返回顶部。鼠标操作需要终端支持鼠标事件；`s` 切换 OUT 带宽、OUT PPS 与总时延平均值，`S` 反转顺序。

`/` 搜索接口/路径名称，`Enter` 打开区间与累计详情，`Esc` 关闭详情或清除过滤，`q` 退出。这些显示操作不会减少记录的路径覆盖。

IN 和 OUT 分别对应**同一条有向路径的起点和终点**。例如 `eth0 -> eth1` 的两组速率都属于这个方向，反向流量在 `eth1 -> eth0` 行。

| 列 | 含义 |
| --- | --- |
| `IN bit/s` / `IN PPS` | 起点保存的 skb 字节数乘 8 / skb 观察次数，除以实际采样间隔。 |
| `OUT bit/s` / `OUT PPS` | 终点 skb 字节数乘 8 / 已完成的 skb 观察次数，除以实际采样间隔。 |
| `Avg` | 当前区间各阶段的时延平均值。 |
| `Min` / `Max` | 当前区间各阶段时延的最小值 / 最大值。 |
| `Newest` | 当前区间最近完成样本的各阶段时延，按单调时钟的完成观测时间选取；不是平均值或刷新时间。阶段完成时间缺失或不一致时显示 `-`，避免拼接不同样本；旧记录缺少这些字段时也显示 `-`。 |
| `PEND` | 已排队、尚未完成或清理的发送关联数量。 |

时延表头分两层，数值统一使用微秒（`us`）：

```text
       Avg       |       Min       |       Max       |      Newest
  S    Q    T    |  S    Q    T    |  S    Q    T    |  S    Q    T
```

`S = Stack`（栈处理）、`Q = Queue`（出口排队）、`T = Total`（总时延）。INPUT 的 Q 显示 `-`，S 与 T 对应相同时间跨度。Total 独立测量；不能相加各阶段的 Min 或 Max 来推算 Total 的 Min 或 Max。点击下层的 S/Q/T 按该阶段、该统计项排序，底部显示完整名称，例如 `Queue max`。

120 列起显示四组完整的 S/Q/T；不足 120 列时每组只显示 T，保留 OUT 速率和更宽的路径名称，其他阶段在详情中查看。160 列起增加 IN 速率与 PEND，带宽和 PPS 各自相邻。列间用纵线分隔，上层组标题横跨三个阶段列。较大的时延必要时使用科学计数法，单位仍为 us；文本快照始终显示全部阶段和速率。

各速率、时延列的最大值分别高亮，Min 高亮最小值。默认按 OUT 带宽降序。FORWARD 在所有排序下都保持两个方向相邻：IN/OUT 速率与 PEND 按两方向合计排序，Min 采用较小的最小值，其余时延列采用两方向中较大的值；没有时延样本的组在升序、降序下均排在末尾。

路径 IN 计数在本机交付或首次进入出口队列、确定路径后入账，使用起点保存的长度；OUT 在本机交付或驱动成功返回时入账。两端可能计入不同区间，桥接分支、GSO 和报文头变化也会影响次数与字节数，因此两列差值不能当作丢包。具体钩子和入账时机见[观测钩子](hooks.md)。

速率对应实际采样区间。时延统计使用完整完成的 skb 样本，不是单个 CPU 的事件或某个函数的耗时抽样。每种时延分布显示样本数、最小值、平均值、近似直方图百分位与最大值，单位微秒（`us`）。最小值、平均值和最大值来自精确观测的时间戳差；由直方图推导的百分位是估算。缺少完成样本不表示零时延。

正常流量使用 64 字节的 per-CPU 区间记录，每次完成在同一条时延记录中更新 S/Q/T。用户态合并各 CPU 分片、已关闭区间和当前区间，得到累计计数与分布，不平均分位数，也不重复写入正常流量累计值。活跃写入阻止区间被提前清理。流量与时延 map 均以路径和区间为键，各允许配置路径数四倍的记录；内存还随内核 possible CPU 数增加。读取缓慢或延迟区间较多时可能触发 `interval_capacity`：共享路径回退仍保留受影响的累计计数或时延样本，但受影响的区间统计不完整。全局流量也按 CPU 汇总，Pending 和在途预算仍由全局控制。

用户态复用批量读取缓冲区，逐批合并 CPU 分片，不复制整张区间表；无样本的时延分片不分配直方图。旧区间在整张表遍历完成后才删除。批量临时缓冲区以 4 MiB 为目标，单条 per-CPU 数据或拥挤的哈希桶可能需要扩大；这不是 BPF map、累计统计或进程总内存上限，不会减少时延样本。

内核辅助函数在同一次事件中复用实时配置，插入失败时复用已取得的预算计数。配置字段仍实时读取，包括原子申请后的容量检查，以及 GSO 子报文之间的停止与父关联检查。指针只在当前调用中复用，全局预算、回收计数和全量时延覆盖保持原有口径。

直方图对每个按 2 的幂划分的时延范围设置四个桶，相对桶宽约为 14% 到 25%；分位数估计采用桶上界，并限制在已观测的最小/最大值之间。

字节计数取各观测点的 `skb->len`：RX core 通常已移除 L2 头，驱动 TX 通常包含 L2 头，INPUT 协议分发处可能已移除 IP 头，因此进出字节数不同不能据此判断丢包。

## 测量边界

队列与驱动发送尝试先检查网络命名空间和接口生命周期，再查 skb 关联表，减少无关流量的查找；探针仍在全主机触发，并非零开销。回收继续按 skb 身份关联，因为释放前设备指针可能已经改变。这些检查不会减少时延样本。

| 路径 | 起点 | 终点 |
| --- | --- | --- |
| INPUT | RX core 内的 `tp_btf/netif_receive_skb` | IPv4 `fentry/ip_protocol_deliver_rcu`、IPv6 `fentry/ip6_protocol_deliver_rcu` |
| OUTPUT | IPv4 `fentry/__ip_local_out`、IPv6 `fentry/__ip6_local_out` | 随后确认成功的 `tp_btf/net_dev_start_xmit` |
| FORWARD | RX core 内的 `tp_btf/netif_receive_skb`，经 IP 路由/NAT 或桥转发 | 随后确认成功的 `tp_btf/net_dev_start_xmit` |

OUTPUT 与 FORWARD 的 `stack` 到 `tp_btf/net_dev_queue` 为止，`queue` 从该入口到成功驱动发送尝试的入口，`total` 独立测量从起点到该入口的时间。`tp_btf/net_dev_xmit` 返回 `NETDEV_TX_OK` 才确认成功，计时终点仍是该次尝试的入口。排队时延包含出口调度与发送重试等待，因此不是纯 qdisc 驻留时间。终点既不是驱动返回时刻，也不是硬件完成或线上发送时刻。INPUT 在 socket 和应用之前结束，没有出口排队阶段。

INPUT 时延不包含 RX core 入口之前的 NIC 接收、NAPI/GRO 和 RPS 工作，也不包含 socket 等待或应用处理。栈时延是 hook 之间的经过时间，不是 CPU 利用率。NAT 可改变报文头，但不会把该次经过视为新连接；这里统计 skb 路径，不是连接 RTT。

接收观测使用直接在 `__netif_receive_skb_core` 内触发的 `tp_btf/netif_receive_skb`，也覆盖列表接收路径，不要求该函数暴露 fentry BTF 目标；该 tracepoint 本身必须提供 BTF 类型。

IPv6 终点是 `ip6_protocol_deliver_rcu` 协议分发器入口，可能早于扩展头处理。该边界不包含后续协议处理函数、socket 等待或应用工作。

## 记录

`-o DIR` 在 `snapshots.jsonl` 中保存区间快照；`summary.json` 保存累计统计与接口身份。`report.html` 是无需外部运行资源的独立离线报告，包含所有已捕获的有向路径，也包含实时屏幕放不下的路径。图表时间轴可能为控制报告大小而抽稀，完整区间快照仍保留在 JSONL 中，所有路径汇总也保留。实时显示行数不限制记录范围。已有记录文件不会被覆盖；再次采集时选择新目录。

## 要求与限制

需要内核支持 BPF syscall/跟踪、在 `/sys/kernel/btf/vmlinux` 提供 BTF，并允许挂载所需接收、IP/桥、队列与驱动观测探针。仅有 Linux 6.6 版本号或已编译的内核符号不足以证明探针可用：运行中的内核必须暴露所需 BTF tracepoint 类型及函数目标，并支持采集器采用的挂载方式。缺少必需探针或挂载失败会报告错误，不能把它们当成接口没有流量。

包括 `br_dev_queue_push_xmit` 在内的必需桥探针要求内核内建 Linux bridge 支持或已加载 bridge 模块，并提供可挂载的函数目标。

在途关联和路径表分别受 `-m`、`-g` 限制；`-m` 为起源关联与发送关联条目的合计预算，不是报文数量。健康计数报告容量、跟踪与统计错误。解释时延或速率前先检查这些计数：未完成、已释放或无法跟踪的 skb 不构成成功时延样本，缺少覆盖不表示没有流量。克隆和 GSO 分段支持在有限跟踪容量内传递身份；skb 数量不一定等于线上报文数。

健康计数说明观测覆盖和诊断情况，不是网络丢包测量。

| 计数 | 含义 |
| --- | --- |
| `association_capacity` | 起源/发送关联的合计预算耗尽，部分关联无法跟踪。 |
| `unrecorded_path_events` | 路径表已满，有向事件无法记录；已有路径继续记录，全局流量计数保留。 |
| `interval_capacity` | 无法存储区间统计，受影响的区间计数/时延不完整；已记录路径仍保留累计计数和回退时延样本。 |
| `late_interval_records` | 活跃写入推迟了已完成区间的读取，数据归入后续快照；累计分布保留样本，受影响的时序区间存在延后。 |
| `map_update_failure` | 跟踪表更新失败；程序不使用定时器。 |
| `unsupported_conversion` | 转换或跟踪深度限制导致无法完整关联。 |
| `unclassified_forward` | 成功的 FORWARD 完成事件没有路由或桥分类；流量总量与有效终点时延仍可用，但转发分类未知。 |
| `expired_associations` / `unknown_exit` | 关联超时，或起源在未观测到完成/已知排队出口时被释放；均不能据此判断网络丢包。 |
| `driver_busy` | 驱动尝试要求重试，是重试诊断，不是丢包计数。 |
| `freed_before_completion` | 已跟踪的排队 skb 在测量终点之前被观测到释放，不代表线上丢包。 |
| `unmatched_queue` / `unmatched_result` | 队列或驱动结果事件缺少匹配的跟踪关联。 |
| `integrity` | 跟踪/统计一致性检查失败，应先检查记录再解释统计。 |
| `newest_contention` | 仅在路径累计回退直方图使用共享最近样本更新时，因并发或嵌套跟踪导致有界更新未完成；正常区间样本使用 per-CPU 分片。其他时延统计继续记录，Newest 在新的有效样本到来前显示 `-`。 |

IPv4/IPv6 分片与重组目前未完整关联。独立的 `fragmentation`、`reassembly` 计数标记这些转换，已跟踪且受影响 skb 的时延样本会被排除；新分配的分片可能无法匹配。应把这些计数理解为关联覆盖缺口，不是已测得的分片/重组时延。

陈旧在途关联达到 30 秒后过期；清理每秒执行一次，与 `-d` 无关，因此保留时间最多约 31 秒。没有在途预留时跳过关联表遍历，随后新增的记录由后续清理检查。过期会报告，不会把未完成 skb 当成完成的时延样本。清理不注入网络报文，也不改变网络配置。

XDP、AF_XDP、硬件卸载绕过流量及非 IP 本机 INPUT/OUTPUT 不在测量范围内。程序不测量 socket/应用时延、NIC 或硬件发送完成，也不测量端到端网络时延。
